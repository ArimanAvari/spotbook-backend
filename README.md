# SpotBook Backend

Backend для курсовой работы «Личный путеводитель».

Сервер написан на Kotlin с Ktor. Он отвечает за регистрацию, вход, JWT-авторизацию, хранение карточек мест, групп, фотографий и синхронизацию с Android-клиентом. Firebase не используется.

## Технологии

- Kotlin
- Ktor
- SQLite
- JWT
- kotlinx.serialization
- Gradle

## Запуск

Проект можно открыть в IntelliJ IDEA как обычный Gradle-проект.

Для запуска из консоли:

```powershell
.\gradlew.bat run
```

Проверка, что сервер поднялся:

```powershell
curl http://localhost:8080/health
```

Обычный адрес сервера:

```text
http://localhost:8080
```

## Структура

Основной код находится в:

```text
src/main/kotlin/com/spotbook/backend
```

Папки проекта:

- `auth` - регистрация, вход, JWT, хэширование паролей;
- `places` - карточки мест и загрузка фото;
- `groups` - группы и привязка карточек к группам;
- `sync` - импорт и экспорт данных;
- `database` - таблицы SQLite и подключение к базе;
- `plugins` - настройка Ktor: routing, security, serialization, database.

## База данных

SQLite-файл создаётся автоматически при запуске:

```text
data/spotbook.db
```

Таблицы:

- `users`
- `groups`
- `place_cards`

Пароль пользователя хранится только в поле `password_hash`.

## Фотографии

Файлы фотографий сохраняются на сервере в папку:

```text
uploads/place_photos
```

В SQLite хранится только путь к файлу.

После загрузки файл можно открыть по адресу:

```text
http://localhost:8080/uploads/place_photos/<file_name>
```

## Авторизация

Пользователь регистрируется и входит по email/password. После успешного входа backend возвращает JWT-токен.

Защищённые запросы должны отправляться с заголовком:

```text
Authorization: Bearer <token>
```

Сервер не доверяет `user_id` от клиента. Текущий пользователь определяется только из JWT.

## Endpoint-ы

Служебные:

- `GET /` - короткая информация о сервере;
- `GET /health` - проверка запуска.

Auth:

- `POST /api/auth/register` - регистрация;
- `POST /api/auth/login` - вход;
- `GET /api/auth/me` - текущий пользователь по JWT.

Places:

- `GET /api/places` - список карточек текущего пользователя;
- `POST /api/places` - создание карточки;
- `GET /api/places/{id}` - детали карточки;
- `PUT /api/places/{id}` - обновление карточки;
- `DELETE /api/places/{id}` - удаление карточки;
- `PATCH /api/places/{id}/status` - изменение статуса;
- `POST /api/places/{id}/photo` - загрузка одной фотографии.

Groups:

- `GET /api/groups` - список групп текущего пользователя;
- `POST /api/groups` - создание группы;
- `DELETE /api/groups/{id}` - удаление группы;
- `GET /api/groups/{id}/places` - карточки внутри группы;
- `POST /api/groups/{groupId}/places/{placeId}` - добавить карточку в группу;
- `DELETE /api/groups/{groupId}/places/{placeId}` - убрать карточку из группы без удаления карточки.

Sync:

- `POST /api/sync/export` - экспорт локальных изменений Android-клиента на сервер;
- `GET /api/sync/import` - импорт всех серверных данных текущего пользователя.

## Синхронизация

MVP использует простую ручную синхронизацию:

- экспорт отправляет локальные карточки и группы со статусами `NOT_SYNCED` и `DELETED`;
- сервер создаёт, обновляет или удаляет записи;
- импорт возвращает все группы и карточки текущего пользователя;
- сложное разрешение конфликтов не реализовывалось специально.

## Демонстрация

Что можно показать:

1. Запуск Ktor backend.
2. Регистрацию и вход пользователя.
3. Получение JWT.
4. Создание, просмотр, редактирование и удаление карточки.
5. Загрузку фотографии карточки.
6. Открытие загруженного файла из папки `uploads`.
7. Изменение статуса карточки.
8. Создание группы.
9. Добавление карточки в группу.
10. Удаление карточки из группы без удаления из общего списка.
11. Экспорт данных с Android на backend.
12. Импорт данных с backend в Android.
13. Проверку данных в SQLite.
